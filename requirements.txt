# --- Core web / HTTP stack -------------------------------------------------

# 2.20.0/2.21.0 still cap urllib3 below botocore's floor — verified against
# actual package metadata, not guessed. 2.22.0 is the first version whose
# urllib3 range overlaps with botocore==1.29.0's range.
requests==2.22.0           # CVE-2018-18074 fixed in 2.20.1+; kept here only as
                           # a resolvable base — see PyYAML/Jinja2/etc. above
                           # for the actual CVE-bearing pins in this file
# urllib3 intentionally left UNPINNED — it's a transitive dependency of both
# requests and botocore. Leaving it unpinned lets pip/uv choose a single
# version that satisfies both ranges (see conflict note at bottom).

Flask==0.12.2              # CVE-2018-1000656 - DoS via crafted JSON payload

# =============================================================================
# NOTE ON DEPENDENCY CONFLICT (why requests is 2.22.0, not 2.19.1):
# All ranges below were verified directly against each package's real
# metadata (egg-info requires.txt), not assumed.
#
# requests==2.19.1 requires  urllib3>=1.21.1,<1.24
# requests==2.20.0 requires  urllib3>=1.21.1,<1.25            (still no overlap)
# requests==2.21.0 requires  urllib3>=1.21.1,<1.25            (still no overlap)
# botocore==1.29.0 requires  urllib3>=1.25.4,<1.27
# -> None of the above overlap with botocore's floor of 1.25.4.
#    A constraints file CANNOT fix this — constraints only steer versions
#    that aren't already pinned/fixed by a direct dependency's own range;
#    they can't force two mutually exclusive fixed ranges to agree.
#
# requests==2.22.0 requires  urllib3!=1.25.0,!=1.25.1,<1.26,>=1.21.1
# botocore==1.29.0 requires  urllib3>=1.25.4,<1.27
# -> These DO overlap: 1.25.4 <= urllib3 < 1.26 (excluding 1.25.0/1.25.1,
#    which is moot since that range is below 1.25.4 anyway) satisfies both.
#    urllib3==1.25.11 (pinned in constraints.txt) is a valid solution.
#
# TRADE-OFF: requests==2.22.0 no longer carries CVE-2018-18074 (fixed in
# 2.20.1). If your goal specifically requires requests==2.19.1's CVE AND
# botocore==1.29.0 installed together, that combination is mathematically
# unsatisfiable in a single environment — use venv_split.sh to isolate
# them into two separate virtual environments instead.
# =============================================================================
